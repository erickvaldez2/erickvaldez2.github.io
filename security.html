The controls.

  1. Email

    SPF and DMARC

    The domain sends no email, so SPF authorizes no servers and DMARC tells receivers to reject anything that fails. This stops phishing that pretends to come from me. I also caught a typo in my own DMARC record during verification (p-reject instead of p=reject), which would have silently disabled it.

    v=spf1 -all v=DMARC1; p=reject;
  2. TLS

    CAA record

    Only the certificate authority GitHub Pages actually uses may issue certificates for the domain. A mis-issued certificate from any other CA would be refused.

    0 issue "letsencrypt.org"
  3. DNS

    DNSSEC

    DNS answers are now signed, so resolvers that validate can detect forged records pointing visitors somewhere else.

  4. Browser

    Content Security Policy

    GitHub Pages can't set custom headers, so the policy ships as a meta tag. Pages may only run their own code and load Google Fonts: no outside scripts, plugins, form posts, base-tag hijacking, or requests to other sites. Inline scripts are still allowed because each game is a single self-contained file; moving them out to use hashes is the next step.

    default-src 'self'; object-src 'none'; base-uri 'none'; form-action 'none'; ...
  5. Privacy

    Referrer-Policy

    Other sites see at most the domain name, never the full page address. Private tool pages send no referrer at all.

  6. Code

    Input validation

    My paper-trading tool restores journal backups from a file. A crafted file could have injected HTML. Now every field is type-checked, limited, and escaped before it reaches the page. I tested it with a malicious backup: the payload was dropped and the valid trade still loaded.

  7. Report

    security.txt and cleanup

    Added a standard security.txt so researchers know how to report issues, and removed unused scripts from the public repo.

  8. Next

    What a free static host can't do

    HSTS and anti-framing headers need a reverse proxy in front of GitHub Pages. That trade-off (certificate renewal vs. extra headers) is the next thing I'm testing.

Check my work.

Everything here is public. Run these from any terminal.

# email authentication
dig +short TXT erickvaldez.com
dig +short TXT _dmarc.erickvaldez.com

# certificate authority restriction
dig +short CAA erickvaldez.com

# DNSSEC (look for the "ad" flag)
dig +dnssec erickvaldez.com A

# browser policy
curl -s https://erickvaldez.com | grep -i content-security-policy

What I took from it.

  • Verify, don't assume.

    The DMARC record looked right in the dashboard. Reading it back is what caught the typo.

  • Know the platform's limits.

    A static host can't send headers, so I moved what I could into the page and wrote down what's left.

  • Small sites still get targeted.

    Spoofed email and look-alike certificates don't need a big target. A domain with your name on it is enough.
